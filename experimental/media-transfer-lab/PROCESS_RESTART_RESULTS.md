# 별도 OS 프로세스 경계의 암호문 이어받기 검증

상태: 구현·Linux 실행 대기. 기존 수신기·스트리밍 암호화·SDK/입장/기기 신뢰/ingress 정책은 변경하지 않음.

새 검증 범위는 8MiB 합성 암호문, 256KiB 청크, 서로 다른 실제 자식 PID의 순차 실행이다. 완료된 반쪽 청크 ACK 후 정상 종료 또는 유휴 ACK 경계 SIGKILL 후 같은 파일로 재실행한다. 동일 청크 재전송·최종 전체 해시·검증된 스트리밍 복호화와 원본/수신 캐시 보존을 확인한다. 나머지 두 시험은 새 프로세스의 MOCK 권한 거부와 변경된 manifest의 정확한 거부 코드 및 평문 출력 0이다.

이 모듈의 권한과 설명자는 합성 fixture이다. 이전 실제 SDK 연결 5/5(run38152247874)와 별개이며, 두 결과를 합쳐 실제 SDK 프로세스 재시작 보장으로 주장하지 않는다. 쓰기 중 종료, 전원 손실/디렉터리 fsync 내구성, 손상 복구, runner 상실, 원자적 권한 철회, 실제 MXC/인터넷/Android/GB/RSS/물리적 삭제는 검증 대상이 아니다.

자식의 로그는 버리고 비밀값/설명자/키/경로는 공개 집계에 넣지 않는다. 자식 종료를 확인한 후 재실행하며, 모든 자식과 임시 owner-only 파일을 정리하고 독립 CI 단계가 전용 marker의 자식 부재와 전체 임시 namespace 부재를 확인한다.

독립 읽기 전용 검토: worker/spec/정리 도구/workflow 생성기에서 중대한 코드 문제 미발견. 실행 증거는 아님. Windows spawn 기반 보조 구문 검사는 응답하지 않아 종료했으며 로컬 실행·구문 통과를 주장하지 않음. Linux 전용 workflow 생성 완료: 이전 후보28개 고정 소스·정책+새 worker/spec/정리3개=31개 해시 guard. mock clock=1000, fixture expiry=2000으로 실제 TTL/시계 복구 시험이 아님.
