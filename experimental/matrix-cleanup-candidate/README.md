## Fixed repeated-startup SIGKILL experiment (pending validation)

repeat-crash preserves each of3 predefined events through3 kills: one while the original server is ready, then two interrupted early startups, and a final full recovery. Each intermediate start requires a changed Docker StartedAt/host PID and PID1 actual Python executable plus anchored module argv. A1000ms observation budget begins after the start/identity commands return; a fixed200ms hold follows that observation. Start-to-confirmed-kill spans are recorded separately. There is no intermediate HTTP readiness wait or probe, so not-ready-at-kill is NOT proved. The original request/ack clocks, same container and/data bind, exit137/non-OOM and stopped-volume encrypted classification for that same event ID are required after every kill. Byte-identical pending ciphertext, an in-flight cleanup transaction or WAL recovery is not established by this classifier. If the ciphertext has already been scrubbed or the fixed process window is unavailable, the scenario fails without resampling, changing scheduler/index/retention, or resetting deadlines. These are startup interruptions, not three fully-ready crashes or host power loss. The pure orchestration tests use a fake adapter and are not runtime evidence. This new mode has not yet passed CI.
