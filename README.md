# 직접대화: 1:1 P2P 메신저 파일럿

두 브라우저를 WebRTC DataChannel로 직접 연결하는 모바일 우선 PWA입니다. 중앙 서비스 서버에 메시지 본문과 대화 기록을 저장하지 않습니다.

## 사용법

### 홈 화면에 추가

- iPhone/iPad: Safari에서 HTTPS 주소를 열고 공유 버튼을 눌러 **홈 화면에 추가**를 선택합니다.
- Android: Chrome에서 HTTPS 주소를 열고 메뉴(⋮)에서 **앱 설치** 또는 **홈 화면에 추가**를 선택합니다.
- 설치 항목이 보이지 않으면 Safari 또는 Chrome에서 페이지를 직접 열어 사용합니다.

1. 각 사용자가 HTTPS 주소를 휴대폰에서 엽니다.
2. 표시 이름을 정하고 내 연결을 만듭니다.
3. 한 사람이 초대 링크를 공유하거나 **코드 복사**로 `dm-...` 연결 코드를 전달합니다.
4. 상대가 링크를 Chrome 주소창에서 열거나, 앱의 **상대 코드 또는 초대 링크로 연결** 칸에 전체 링크 또는 `dm-...` 코드를 붙여 넣습니다.
5. 양쪽이 안전 코드를 별도 통화 또는 대면으로 비교하고, 같을 때 각자 확인 버튼을 누릅니다.
6. 양쪽이 확인해야 입력창이 열립니다. 두 사람이 앱을 화면에 열어 둔 상태에서 실시간으로 대화합니다.
7. Wi-Fi와 모바일 데이터 사이를 전환하면 기존 직접 연결이 끊길 수 있습니다. 이 경우 상대 앱을 다시 화면에 열고 연결 버튼을 다시 누릅니다.

## 구현된 범위

- 1:1 텍스트 실시간 전송
- WebRTC DataChannel 전송 구간 DTLS 암호화 (앱 계층 E2EE는 아님)
- ECDSA P-256 기기 키와 표시 이름을 포함한 서명 handshake
- 양쪽 안전 코드 확인 교환 완료 후에만 송수신 허용
- 확인한 상대 키 로컬 저장
- 전달 확인(ack)
- 상대가 바뀌면 이전 대화 화면과 작성 문구를 분리하고, 같은 상대의 일시적 재연결에는 초안을 보존
- 앱 프로세스가 살아 있을 때의 선택형 일반 알림과 대화 중 화면 켜짐 유지
- 새 서비스 워커가 준비되면 사용자가 선택해서 적용하는 업데이트 안내
- WebRTC 직접 연결, 기기 서명 확인, 안전 코드 계산 단계를 구분해 표시하고 직접 연결이 15초 이상 멈추면 재시도 화면으로 복귀
- 기본 클라이언트 제한: 한 방향 분당 30개, 연결당 임시 표시 500개
- PWA 홈 화면 설치와 오프라인 앱 셸
- 메시지 본문과 대화 이력의 서버 저장 없음

## 중요한 제한

- 공용 PeerJS Cloud를 연결 신호에 사용합니다.
- 메시지 본문은 신호 서버를 통하지 않지만 연결 코드, IP, 접속 시각 등 메타데이터가 처리될 수 있습니다.
- TURN 서버가 없어 Wi-Fi와 모바일 데이터처럼 서로 다른 네트워크 조합, 일부 회사망, VPN, 통신망에서는 연결에 실패할 수 있습니다.
- 두 사람이 동시에 온라인이고 앱을 전면 화면에 열어 두어야 합니다. 앱이 닫히거나 Android가 브라우저/PWA를 정지하면 상대가 연결 코드를 찾을 수 없습니다.
- Android 알림 권한을 허용하면 앱 프로세스가 살아 있는 동안 일반적인 ‘새 메시지’ 알림을 시도합니다. 이는 Web Push가 아니며, 연결이 살아 있으면 앱 복귀 후 밀린 데이터가 표시될 수 있지만 운영체제가 앱을 종료한 경우에는 알림과 전달 모두 보장되지 않습니다.
- 앱을 빠르게 종료·재실행해 이전 PeerJS 등록이 잠시 남더라도 저장된 `dm-...` 연결 코드를 자동 변경하지 않고 같은 코드로 재연결을 시도합니다.
- 현재 오프라인 수신함, 푸시 알림, 서버 보관 메시지가 없습니다. 앱이 닫힌 상대에게 메시지를 전달하는 기능은 TURN 추가만으로 해결되지 않으며 별도의 상시 접속·푸시·암호화 대기열 설계가 필요합니다.
- 새로고침하거나 앱을 닫으면 화면 메시지는 사라집니다. 새 버전 적용 전에도 현재 연결·메시지·초안이 사라질 수 있음을 안내합니다.
- 신호 경로에서 키가 대체되는 위험은 안전 코드를 별도 신뢰 채널로 실제 대조해야 완화됩니다. 대조만으로 호스팅/배포 계정 침해, 기기 악성코드, 상대의 캡처/촬영, 피싱을 막지는 못합니다.
- 앱 계층 E2EE 프로토콜이나 인증된 계정-키 디렉터리가 없습니다. DTLS 전송 암호화를 검증된 상대 신원 보장으로 오해하지 마세요.
- 독립 보안 감사를 받지 않았습니다. 메시지 속도 제한은 클라이언트 단에서만 적용되며, 신호 서버 측 남용 방지·계정 제재·DDoS 방어가 없습니다. 고위험 개인정보, 의료·금융·법률·영업비밀에는 사용하지 마세요.

## 배포

정적 파일을 HTTPS 호스팅에 배포합니다. GitHub Pages에서 별도 빌드 없이 동작하도록 작성했습니다.
