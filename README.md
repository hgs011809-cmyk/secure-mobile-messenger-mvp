# 직접대화: 1:1 P2P 메신저 파일럿

두 브라우저를 WebRTC DataChannel로 직접 연결하는 모바일 우선 PWA입니다. 중앙 서비스 서버에 메시지 본문과 대화 기록을 저장하지 않습니다.

## 사용법

### 홈 화면에 추가

- iPhone/iPad: Safari에서 HTTPS 주소를 열고 공유 버튼을 눌러 **홈 화면에 추가**를 선택합니다.
- Android: Chrome에서 HTTPS 주소를 열고 메뉴(⋮)에서 **앱 설치** 또는 **홈 화면에 추가**를 선택합니다.
- 설치 항목이 보이지 않으면 Safari 또는 Chrome에서 페이지를 직접 열어 사용합니다.

1. 각 사용자가 HTTPS 주소를 휴대폰에서 엽니다.
2. 표시 이름을 정하고 내 연결을 만듭니다.
3. 한 사람이 초대 링크를 공유합니다.
4. 상대가 링크를 열고 연결을 수락합니다.
5. 양쪽이 안전 코드를 별도 통화 또는 대면으로 비교하고, 같을 때 각자 확인 버튼을 누릅니다.
6. 양쪽이 확인해야 입력창이 열립니다. 두 사람이 앱을 연 상태에서 실시간으로 대화합니다.

## 구현된 범위

- 1:1 텍스트 실시간 전송
- WebRTC DataChannel 전송 구간 DTLS 암호화 (앱 계층 E2EE는 아님)
- ECDSA P-256 기기 키와 표시 이름을 포함한 서명 handshake
- 양쪽 안전 코드 확인 교환 완료 후에만 송수신 허용
- 확인한 상대 키 로컬 저장
- 전달 확인(ack)
- 기본 클라이언트 제한: 한 방향 분당 30개, 연결당 임시 표시 500개
- PWA 홈 화면 설치와 오프라인 앱 셸
- 메시지 본문과 대화 이력의 서버 저장 없음

## 중요한 제한

- 공용 PeerJS Cloud를 연결 신호에 사용합니다.
- 메시지 본문은 신호 서버를 통하지 않지만 연결 코드, IP, 접속 시각 등 메타데이터가 처리될 수 있습니다.
- TURN 서버가 없어 일부 회사망, VPN, 통신망에서는 연결에 실패할 수 있습니다.
- 두 사람이 동시에 온라인이고 앱을 열어 두어야 합니다.
- 새로고침하거나 앱을 닫으면 화면 메시지는 사라집니다.
- 신호 경로에서 키가 대체되는 위험은 안전 코드를 별도 신뢰 채널로 실제 대조해야 완화됩니다. 대조만으로 호스팅/배포 계정 침해, 기기 악성코드, 상대의 캡처/촬영, 피싱을 막지는 못합니다.
- 앱 계층 E2EE 프로토콜이나 인증된 계정-키 디렉터리가 없습니다. DTLS 전송 암호화를 검증된 상대 신원 보장으로 오해하지 마세요.
- 독립 보안 감사를 받지 않았습니다. 메시지 속도 제한은 클라이언트 단에서만 적용되며, 신호 서버 측 남용 방지·계정 제재·DDoS 방어가 없습니다. 고위험 개인정보, 의료·금융·법률·영업비밀에는 사용하지 마세요.

## 배포

정적 파일을 HTTPS 호스팅에 배포합니다. GitHub Pages에서 별도 빌드 없이 동작하도록 작성했습니다.

## 의존성

- PeerJS 1.5.5, 저장소에 고정된 minified 파일로 포함
- 외부 분석, 광고, 세션 재생 스크립트 없음
