# 비동기 메시지와 양쪽 삭제: 요구사항 및 설계 게이트

## 확인된 현재 상태
- 앱 v0.6.1: 인증된 P2P 텍스트, 안전 코드, 자체 TURN, 본문 없는 Web Push 접속 알림.
- Android 2대에서 Wi-Fi↔모바일 데이터 텍스트 송수신과 안전 코드 일치, 실제 푸시 수신은 사용자가 확인.
- 알림 클릭 후 앱 열기는 아직 별도 확인이 필요하다.
- NCP secure-msg-pilot-1: 1 vCPU, RAM 1GB, 기본 디스크 10GB. 기존 서버 자원·비용 변경은 하지 않았다.

## 사용자 확정 요구사항
1. 등록된 상대끼리는 동시 접속 없이 메시지를 보낼 수 있어야 한다.
2. 새로고침 또는 앱 재실행 후에도 메시지를 볼 수 있어야 한다.
3. 1:1 대화의 어느 한쪽이 양쪽 삭제를 하면 상대 승인 없이 처리한다.
4. 온라인 상대는 삭제를 동기화하고, 오프라인 상대는 다음 동기화 때 삭제를 반영한다.
5. 현재 푸시·연결 작업을 먼저 완료한 뒤 구현한다.

## 제안 기본값: 구현 전 확정 필요
- 보관 기간: 사용자가 삭제할 때까지. 단, 저장 한도와 운영 비용은 별도로 정한다.
- 메시지 단위와 대화 전체 삭제를 구분한다.
- 삭제된 메시지는 오래된 동기화 응답·재전송으로 다시 나타나면 안 된다.
- 삭제 이벤트는 대화 참여자 권한과 무결성을 검증한다.
- 새 기기 또는 분실 복구 시 과거 기록 복원 정책을 별도로 정한다.

## 보안 게이트
- 기존 WebRTC DTLS를 앱 계층 E2EE로 오인하지 않는다.
- 서버에는 메시지 평문이나 복호화 개인키를 저장하지 않는다.
- 유지보수 가능한 검증된 E2EE SDK/프로토콜을 선택한다. 자체 암호 프로토콜을 급히 만들지 않는다.
- 서버가 임의로 상대 키를 바꾸는 경우 감지하고 재검증하도록 한다.
- 삭제 동기화는 앱이 통제하는 저장소에 한정된다. 캡처·내보내기·외부 백업·변조 클라이언트의 복사본 삭제를 보장하지 않는다.
- 신호/P2P 연결은 비동기 큐와 역할을 구분하며 추후 음성통화에 재사용할 수 있다.

## 다음 구현 전 확인
- E2EE SDK와 서버 구성 선택.
- 1GB 서버에 새 구성 적용 가능 여부와 여유 자원 검증.
- 증설 또는 외부 서비스가 필요하면 비용 발생 전에 사용자 승인.
- 개인정보 로그 정책, 데이터 보관 한도, 삭제 후 백업 보관 정책.

이 문서는 요구사항과 설계 조건이며, 오프라인 메시지·기록 보관·양쪽 삭제가 이미 구현되었다는 뜻이 아니다.

## E2EE 경로 검토 결과: Matrix 우선 후보, 아직 도입 확정 아님
- 유지보수되는 matrix-js-sdk와 Rust/WASM crypto를 우선 후보로 한다. 서버 저장과 /sync, 1:1 E2EE, redaction의 기존 표준을 활용할 수 있다.
- OpenMLS는 유지보수되고 코어 감사가 있으나 공식 WASM 바인딩은 실험 상태이며 저장·동기화·삭제 앱 프로토콜은 별도로 만들어야 한다. 이 파일럿에서 자체 암호 프로토콜을 만드는 경로는 우선하지 않는다.
- Matrix 도입은 단순 큐 추가가 아니라 계정 프로비저닝, 암호 키/기기 검증, 초대 전용 방, 토큰 보호, 푸시 연결과 UI 전송 계층 이관이 필요하다.
- 기존 P256 안전 코드를 Matrix 키 검증과 동일하다고 표시하지 않는다. 기존 신원과 새 암호 키 사이의 보안 검토 및 사용자 재검증이 필요하다.

### 삭제 요구사항과 충돌: 승인 또는 대안 설계 필요
- Matrix redaction은 즉시 메시지 본문 접근과 표시를 차단하는 표준 기능이나 이벤트와 삭제 흔적은 남는다.
- Synapse는 redaction 전 이벤트를 기본 7일 보관한다. redaction_retention_period를 0으로 설정해도 정리 주기 때문에 원문 암호문 제거가 최대 약 5분 지연될 수 있다.
- 따라서 기존 요구인 서버 보관분 즉시 삭제를 물리적인 즉시 제거로 해석하면 기본 Synapse만으로 충족됐다고 주장할 수 없다.
- 즉시 접근 차단과 5분 이내 암호문 정리를 허용할지, 아니면 별도 보관/삭제 계층이 필요한지 사용자와 확정해야 한다.
- 한쪽이 상대 메시지를 redact할 수 있도록 방 권한을 설정할 수 있으나, 그 권한은 메시지 이벤트만이 아니라 방 이벤트 전체에 적용되는 점을 보안 검토해야 한다.
- 오프라인 기기의 삭제 반영은 다음 동기화이며 변조 클라이언트·캡처·내보내기·외부 백업 회수는 보장하지 않는다.

### 운영 게이트
- 현재 1GB 서버에 추가 홈서버/DB를 안전하게 함께 올릴 수 있는지 검증되지 않았다. 비용이나 서버 증설을 승인 없이 실행하지 않는다.
- 현재 성공한 P2P·Web Push를 유지한 채 별도 테스트 구성에서 검증한다.
- 아직 메시지 저장·E2EE 새 프로토콜·양쪽 삭제 코드나 서버는 배포하지 않았다.

## 독립 로컬 검증 결과
- matrix-js-sdk 43.0.0의 Rust/WASM 암호 엔진 의존성인 matrix-sdk-crypto-wasm 18.7.0을 운영 앱과 분리해 검증했다.
- CLI npm 설치는 작업 경로 처리 오류와 CLI DNS 제한으로 실패했으며, 브라우저 네트워크로 공식 tarball을 다운로드해 우회했다.
- 공식 npm SHA-512 무결성 일치 테스트와 합성 메시지 암호화 테스트가 통과했다. 서로 다른 기기의 공개 서명키가 다르고, 암호문에 본문이 없고, 보낸 기기의 로컬 복호화는 성공하며 키가 없는 기기와 변조된 암호문은 복호화에 실패했다.
- 총 2개 로컬 테스트 통과, 실행 프로세스 종료 코드 0. 개인키나 실제 메시지를 출력하거나 서버에 전송하지 않았다.
- 이는 Node 기반 로컬 암호 엔진 smoke test이며 Android 브라우저, 기기간 키 교환, 신원 검증, 실제 서버 저장·삭제·동기화 검증은 아니다.
- 운영 앱, NCP 서비스, 서버 비용과 등록 정보는 변경하지 않았다.
